# PostgreSQL baseline

This directory is the canonical, immutable payload for Request Engine Alembic revision 0001_initial.

The current baseline (2026-10-23 rebaseline) was materialized from the audited PostgreSQL 18.6 effective model at historical Alembic head 0047_reservation_calendar_read and commit afbbe397681732399702aad34da917e15d503018. It collapses the former 0001_initial (itself the 0094 rebaseline of 2026-09) plus 0002..0047. The proof, recorded in docs/audits/postgresql-rebaseline-0047.md, was:

1. the former chain installed on a clean PostgreSQL 18 cluster (A);
2. the new 0001 alone installed on an independent clean PostgreSQL 18 cluster (B);
3. schema, role (17 roles) and normalized seed catalogs of A and B were equivalent;
4. `pg_dump --schema-only` of A and B (comments, owners and ACLs included) was byte-identical;
5. baseline integrity (third clean cluster plus the installation-identity probe) and the multi-database proof passed.

Files:

- `0001_roles.sql` — the ten bootstrap roles (exact topology, no memberships/settings), unchanged since the 0094 baseline;
- `0001_extension_roles.sql` — the historical fail-closed ensure blocks of the seven extension roles, run before the schema;
- `0001_schema.NN.sql` — the pg_dump-derived schema and migration-owned seed payload;
- `0001_post_install_audit.sql` — extension-role audits that need the installed schema;
- `seed-data-catalog.json` — the normalized seed/reference state.

manifest.json pins every payload checksum, the bootstrap and extension role attributes, the seed/reference-state checksum, the accepted effective-model counts, the analyzer findings explicitly accepted at the cut and the proof provenance. loader.py verifies those checksums and role contracts before and after 0001_initial executes the SQL.

After this rebaseline, migrations/versions/0001_initial.py is the only historical revision. Future schema evolution appends new 0002+ revisions. Never regenerate this payload merely to make a later migration easier; another destructive rebaseline requires a new explicit audit and clean-cluster equivalence proof.

## Installation-local identity

The rebaseline preserves migration-owned reference data, but it deliberately does **not** freeze the identity of the CI database that produced the source artifact. Every fresh installation generates a new Platform Instance UUID, built-in native-authority UUID, built-in workload-authority UUID and creation timestamps using the PostgreSQL defaults (gen_random_uuid() / clock_timestamp()).

seed-data-catalog.json therefore normalizes only those installation-local fields to named placeholders. All remaining seed/reference state stays exact. Baseline-integrity CI installs the same 0001 twice and fails if any of the three installation UUIDs is reused.

## Provenance vs canonical payload

The canonical payload is intentionally **not byte-identical** to the raw source dump. The raw dump captured installation-local UUIDs and timestamps from the source database; shipping those literal values would clone that installation's identity into every new Request Engine deployment.

The canonical baseline therefore rewrites only:

- built-in native/workload authority UUIDs, which are generated by PostgreSQL defaults on each install;
- `platform_instance`, which binds to those newly generated authorities;
- installation-local creation timestamps, which are generated on each install;
- `COMMENT ON EXTENSION`, which is dropped because `CREATE EXTENSION` recreates it;
- four leftmost `length(x) >= a AND length(x) <= b` CHECK conjuncts, which are restored to their original `BETWEEN` source form. Replaying the deparsed text would flatten the nested AND, so the stored expression tree would differ.

With these rewrites the installed DDL is byte-identical to the source. Seed/reference data is verified semantically after normalizing only those documented installation-local fields. `manifest.json` records both the original candidate artifact hashes and the final canonical payload hashes so provenance and accepted runtime truth cannot be confused.
